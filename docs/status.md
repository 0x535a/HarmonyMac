# 状态与验证范围

更新于 2026-11-19。目标硬件为 Apple M3 Pro / J514S。开发分项在 macOS + UTM/QEMU 中验证，原生结果来自 U393 外置测试盘及同一台 J514S 的启动日志。本页综合不同轮次的结果，各项以对应环境为准。

## 最新原生候选

原生软件渲染基线 R1 已在独立 ext4 根分区进入原装桌面并正常关机。后续差量接入 Asahi，实机确认渲染器为 **Apple M3 Pro (G15S B1)**。Apple DCP 先后确认 **3024×1890 @ 120 Hz** 和实验性全高 **3024×1964 @ 120 Hz**，全高增加顶部 74 行，刘海避让仍待验证。

全画幅启动动画和 GBM/DMA-BUF 直送已在较早的实机轮次上屏。之后的内容诊断覆盖 7,285 次直送翻页，未见旧帧重新上屏或合成后的跳变，7,200 次下屏复检未发现扫描期间缓冲被改写。鼠标顿挫仍可见。同步等待翻页的中位时间约 12.6 ms，已实现基于 KMS out-fence 的异步提交，本地 36 帧逐像素通过，最新单屏版上，用户确认鼠标顿挫已解决。输入到出画延迟和实际新帧速率待量化。

随后默认开启 HDMI 多屏的候选发生黑屏。原装 init 和系统服务已就绪，动画进程也在提交，`composer_host` 却反复崩溃。崩溃栈集中在 VSync 回调。原装服务只保存一份回调强引用，VDI 按输出保留裸指针，再次注册可能释放先前回调。最新写盘回退为 **默认单屏**，保留异步提交、孵化服务恢复和 J514 音频候选。已读回核对，用户随后确认该组合实机正常启动并可用。

## 联合验收

最终候选仍需验证至少两个原装应用的交互和持久化，连续操作至少 30 分钟，同一构建至少三次原生冷启动及 Aurora 救援。此前各轮的日志、帧图和磁盘留在开发归档。

开发候选可结束 OOBE 进入桌面。商业激活仍在 TEEC 初始化及 SoC 证明处中断。正式 enforcing 策略、权限隔离、硬件密钥和生物识别独立验收；华为账号、云服务及应用市场尚未验证。
